# 小米 C700 + 绿联 NAS 本地照护观察部署指南

## 1. 目标与已确认的配置

本方案只在绿联 DH4300P NAS 上处理影像，不上传录像、音频或事件片段到云端。

| 项目 | 配置 |
| --- | --- |
| NAS | 绿联 DH4300P，UGOS 1.18.0.0093 |
| 硬件 | RK3588C、8 核、8 GB 内存 |
| 摄像头 | 先接入一路小米 C700 |
| 录像目录 | `/volume2/小米摄像机/XiaomiCamera_00_B88880639745` |
| 视频格式 | 按日期/时间保存的 MP4，包含音频 |
| 报告时间 | 每日 18:00 |
| 报告范围 | 当天 00:00–18:00 |
| 通知方式 | 163 邮箱 SMTP |
| 隐私设置 | 只检测哭声和互动时长；不转录成人对话 |
| 告警偏好 | 宁少勿滥 |

## 2. 能力边界

录像通过 SMB 写入 NAS。分析服务只能处理**已经写入完成**的 MP4 文件，不能读取正在写入中的文件。

示例文件覆盖约 7 分钟，因此告警通常会在事件发生至少约 7 分钟后出现，实际延迟可能更长。它仅能发送“建议查看”的提示，不能代替成年人看护、紧急报警系统或医疗判断。

自动分析可以识别或汇总的内容包括：

- 已有录像覆盖的时间段；
- 可见的瓶喂、哄睡、成人出现与互动候选片段；
- 哭声候选时段及持续时间；
- 报告中的时间线、趋势和需要人工复核的片段。

以下内容不能仅凭单一普通摄像头可靠判断，禁止自动下结论：

- 实际摄入奶量、健康状态、是否已睡着；
- 相机盲区中是否有人照护；
- 窒息、危险姿势、虐待或照护者能力；
- 成人谈话的内容或意图。

## 3. NAS 目录与权限

在 NAS 文件管理器中创建如下目录：

```text
/volume2/docker/baby-monitor/
├── config/       # 非敏感配置
├── state/        # 已处理文件与任务状态
├── reports/      # 每日报告
├── events/       # 被标记的短事件片段
├── logs/         # 运行日志
└── secrets/      # 邮件授权信息
```

保持原录像目录不变：

```text
/volume2/小米摄像机/XiaomiCamera_00_B88880639745
```

容器的权限必须满足：

1. 对录像源目录只读挂载；不得删除、移动、改名或写入原始录像。
2. 仅可写入 `/volume2/docker/baby-monitor/`。
3. 不授予访问 NAS 其他共享文件夹的权限。
4. 不映射 SMB 445 端口或任何公网端口。

推荐的容器挂载关系：

```text
/volume2/小米摄像机/XiaomiCamera_00_B88880639745  -> /media/source:ro
/volume2/docker/baby-monitor/config                 -> /app/config:ro
/volume2/docker/baby-monitor/state                  -> /app/state
/volume2/docker/baby-monitor/reports                -> /app/reports
/volume2/docker/baby-monitor/events                 -> /app/events
/volume2/docker/baby-monitor/logs                   -> /app/logs
/volume2/docker/baby-monitor/secrets                -> /run/secrets:ro
```

## 4. 163 邮件设置

1. 登录 163 网页邮箱。
2. 在“设置”中打开 POP3/SMTP/IMAP。
3. 启用 SMTP，并生成客户端授权密码。
4. 在 NAS 上创建文件：

```text
/volume2/docker/baby-monitor/secrets/mail.env
```

文件内容如下。将尖括号内项目替换为你自己的值；不要把此文件上传到 Git、聊天工具或截图中。

```dotenv
SMTP_HOST=smtp.163.com
SMTP_PORT=465
SMTP_TLS=true
SMTP_USER=<完整163邮箱地址>
SMTP_PASSWORD=<163客户端授权密码>
MAIL_FROM=<完整163邮箱地址>
MAIL_TO=<接收日报的邮箱地址>
TZ=Asia/Shanghai
```

只允许 NAS 管理员和运行容器的服务账号读取 `mail.env`。

## 5. Docker 项目参数

在绿联 Docker 应用中创建项目，建议项目名称：

```text
baby-monitor
```

运行参数：

| 参数 | 推荐值 | 原因 |
| --- | --- | --- |
| 重启策略 | `unless-stopped` | NAS 重启后自动恢复 |
| CPU 上限 | 4 核 | 防止影响录像与 NAS 日常服务 |
| 内存上限 | 4 GB | 为系统和其他服务保留内存 |
| 网络 | 默认 bridge 网络，不发布端口 | 本方案只发送邮件，无需对外提供网页 |
| 时区 | `Asia/Shanghai` | 保证 18:00 任务正确触发 |
| 录像源挂载 | 只读 | 防止误删原始证据 |

容器应包含以下内部任务：

1. **文件稳定性检查**：MP4 文件大小连续 10 分钟不变化才进入队列。
2. **媒体探测**：读取时长、分辨率、帧率、视频编码和音频编码；无法解码时记录到报告。
3. **事件筛选**：先按低帧率抽样画面、分析音频活动；只对候选时段进一步处理。
4. **事件归档**：仅保存被报告标记的短片段，不复制全天原视频。
5. **日报生成**：18:00 汇总当天 00:00–18:00 已完成且已分析的录像。
6. **保留期清理**：清理事件片段、日报和日志，不触碰原始录像。

不要对全天 MP4 逐帧执行视觉模型。RK3588C 和 8 GB 内存更适合“先筛选、后分析”的方式。

## 6. 处理规则

### 6.1 文件处理

```text
扫描频率：每 5 分钟
文件稳定时间：10 分钟
视频抽帧：默认每秒 1–2 帧
候选片段精查：仅在检测到活动、人物或哭声候选时提高采样率
音频：仅检测哭声候选、音量/活动变化；不保存谈话文本
```

### 6.2 7 天基线期

前 7 天只生成日报，不发哭闹或“未见回应”告警。每天人工打开报告对应的时间戳，标记误报或漏报，再调整阈值。

基线报告以观察为主：

- 可见瓶喂候选时段与持续时间；
- 可见哄睡、安静休息、醒来和哭闹片段；
- 可见成人进入画面与互动片段；
- 录像缺失、损坏或无法解码时段。

宝宝目前的家庭参考节律：

```text
喂养：母乳瓶喂，约每 3 小时一次
睡眠：约每 2–3 小时需要哄睡
```

系统只提示“与已记录节律不一致的可见现象”，不能把未拍到的事项判定为未发生。

### 6.3 正式告警

基线期结束且人工验证结果可接受后，依次启用：

| 规则 | 初始阈值 | 通知文案 |
| --- | ---: | --- |
| 持续哭声候选 | 连续至少 10 分钟 | 请查看：持续哭闹候选 |
| 哭声后未检测到成人进入画面 | 至少 15 分钟 | 请查看：哭闹后未见可检测回应 |
| MP4 无法读取或分析服务故障 | 单次 | 监控分析异常 |
| NAS 可用空间过低 | 小于 15% | NAS 存储空间不足 |

“未检测到成人”不等于“无人照护”，可能只是镜头盲区或识别失败；邮件必须包含这个说明。

## 7. 每日邮件报告

邮件主题：

```text
宝宝照护观察日报｜YYYY-MM-DD｜00:00–18:00
```

报告内容：

```text
一、分析覆盖
- 成功分析的录像时段
- 未覆盖、未完成或失败的文件

二、可见日程
- 瓶喂候选时段与持续时间
- 哄睡/安静休息候选片段
- 哭闹候选片段
- 成人出现与互动片段

三、需要人工复核
- 时间戳
- 事件类型
- 本地事件片段路径
- “自动检测结果，建议查看原始录像”的提示

四、趋势与建议
- 与过去 7 天基线的变化
- 仅给出可执行、非评判性的建议

五、系统状态
- NAS 剩余可用空间
- 分析失败文件
- 下次任务时间
```

## 8. 存储保留策略

原始录像、事件片段和报告必须分开处理：

| 数据 | 建议保留期 | 清理者 |
| --- | ---: | --- |
| 原始小米录像 | 由 2 TB 空间策略决定 | NAS 录像清理策略 |
| 事件短片 | 30 天 | 分析服务 |
| 每日报告 | 90 天 | 分析服务 |
| 日志 | 30 天 | 分析服务 |

在绿联 NAS 的存储/共享文件夹设置中启用“空间达到 85% 后删除最旧录像”或同等功能。不要等磁盘写满再清理；磁盘写满会导致摄像头录像和数据库都不稳定。

分析服务禁止删除 `/volume2/小米摄像机/` 下的任何文件。

## 9. 上线前验证

完成部署后，按以下顺序测试：

- [ ] 容器能启动，并在 NAS 重启后自动恢复。
- [ ] 容器只能读取录像源，不能创建或删除其中的文件。
- [ ] 容器能向 `state`、`reports`、`events`、`logs` 写文件。
- [ ] 能读取一段历史 MP4 的时长、音视频编码、分辨率和帧率。
- [ ] 写入中的 MP4 不会被处理。
- [ ] 文件写入完成后，约 10 分钟内会被加入处理队列。
- [ ] 163 测试邮件能成功送达。
- [ ] 每日 18:00 的定时任务按 `Asia/Shanghai` 正确触发。
- [ ] 人工抽查至少 10 段已有录像，核对报告的时间戳。
- [ ] 连续运行 7 天后，NAS 的录像、CPU、内存和可用空间仍然稳定。

## 10. 下一步：选择本地模型实现

本文件描述了安全的部署配置和行为规则，但“哭声分类、人物/活动检测、事件汇总”仍需实际的 ARM64 本地分析程序实现。

选择本地模型时必须满足：

1. 支持 Linux ARM64；
2. 不依赖云端 API；
3. 可以只分析本地挂载的 MP4；
4. 可以关闭语音转录；
5. 输出可审计的时间戳和本地事件路径；
6. 在 4 CPU 核、4 GB 内存限制下稳定运行。

部署任何第三方镜像前，先核对其 ARM64 支持、镜像来源、更新记录与隐私说明。不要为“更智能”的识别效果而把儿童影像上传到未明确审查的数据服务。
